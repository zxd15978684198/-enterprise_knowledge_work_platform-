# ADR-0011：身份域与来源审阅范围（C-07 决策）

- 日期：2026-10-29
- 状态：**提议**（身份域模型属产品/安全裁决，工程侧只提供选项与约束）
- 依据：`docs/poc/07_Contract_Closure.md:21`（C-07 `BLOCKED`）、`:119` 起章节；`Phase0_Full_Gate_Review.md` §6.1 ADR-NEW-5、§6.3 DG-7；`05_Phase0_Acceptance.md:72`

## 背景

C-07 是实验契约中唯一 `BLOCKED` 项：「P0 来源审阅草案可实验，身份/API/字段范围待决定」（`docs/poc/07_Contract_Closure.md:21`）。它阻塞的不是某段代码，而是**来源审阅 API 的字段与身份委托范围**：在身份域未定时，任何字段冻结都会把猜测写进契约。`05:72` 要求「身份域/来源审核 API 和字段例外不可留给实现猜」，因此工程侧不能自行拍定，只能把缺口写成决策项。

已确定的部分（不受本 ADR 影响）：所有业务资源必须带 `workspace_id`，所有访问由后端校验 principal、工作区与资源权限，不信任客户端提交的作用域；T03 的合成身份与 Scope、T29 的越权用例均建立在此前提上。

## 决策提议

三个选项由产品/安全裁决，工程给出后果评估：

| 选项 | 内容 | 后果 | 适用条件 |
| --- | --- | --- | --- |
| A | **身份域收敛为「产品内 principal + workspace + 角色」**，外部 IdP 委托与跨域联邦留到 P1+ | 来源审阅 API 可只依赖 `principal_id`/`workspace_id`/`role` 三要素；C-07 可关闭；新增一处「不实现外部委托」的显式声明 | 首发为自建部署、不接第三方身份（推荐，最省） |
| B | 引入 OIDC 委托（外部 IdP 换 token → 内部 principal 映射） | 需要新增 TDD 身份章节、token 校验与映射表、委托链审计；T03/T11/T13/T27/T29 需补跨域用例 | 首发即需对接企业 IdP |
| C | 维持 `BLOCKED`，来源审阅 API 冻结不实现 | 来源审阅能力从 P0/P1 首发中移除；DG-7 长期生效 | 产品确认首发不需要来源审阅 |

无论选哪个，工程侧先固定两条不变量：(1) 后端一律以服务端解析出的 principal 为准，不接受客户端声明的作用域；(2) 来源审阅相关表/字段在裁决前不冻结，写入 `07_Contract_Closure.md` 的「待决」区。

## 替代方案

1. 让实现先用「临时身份字段」顶着，等以后再说：正是 `05:72` 明令禁止的「留给实现猜」，拒绝。
2. 只做 API 不做权限校验（P0 内网可信假设）：与 AGENTS.md「不得信任客户端提交的作用域」冲突，拒绝。
3. 用 OAuth2 client credentials 代替用户身份：把「谁审阅了来源」变成「哪个服务审阅了」，会导致审计链缺失，需先补审计模型，暂不采纳。

## 后果与验证条件

后果：选 A 会让 C-07 从 `BLOCKED` 变为 `DEFINED`，但要在 TDD 01 身份章节写明「不实现外部 IdP 委托」；选 B 会显著扩大 T03/T29 的用例面。验证条件：(1) C-07 的状态变更必须有本 ADR 的接受记录；(2) `07_Contract_Closure.md` 中来源审阅字段从「待决」移出时必须附决策出处；(3) T03/T11/T13/T27/T29 的越权用例保持全绿，跨工作区隔离不得回退；(4) 发布文档不得声称支持未裁决的身份形态。
