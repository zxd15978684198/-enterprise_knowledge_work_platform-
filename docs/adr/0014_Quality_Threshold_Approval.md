# ADR-0014：质量阈值与基线批准流程

- 日期：2026-10-29
- 状态：**提议**（阈值数值需产品/测试负责人批准；工程侧先固定流程与留证方式）
- 依据：`05_Phase0_Acceptance.md:74`（Recall@5 0.85 / 引用一致性 0.95 未校准时该项不 PASS）；`Phase0_Full_Gate_Review.md` §6.1 ADR-NEW-8、§6.3 DG-3/DG-4；`poc09-report.md`

## 背景

`05:74` 给出的两个候选阈值——检索 Recall@5 ≥ 0.85、引用一致性 ≥ 0.95——当前**既没有校准，也没有批准人**：PoC-09 的 ANN 部分因缺 pgvector 标 `NOT_RUN`，检索只做了关键词/结构化两路对照；引用一致性受限于没有真实 chat 模型（PoC-08 与 PoC-06 都是替身）。`05:74` 明确「未校准时该项不 PASS」，`05:75` 要求「记录实际差距和硬件边界」。

问题不在于数值定高了还是定低了，而在于**没有流程**：谁有权批准、基于什么样本集批准、改阈值时旧结果如何留存，都没有成文。于是任何一次「先写个 0.85 看着差不多」都会变成事实标准。

## 决策提议

1. **建立阈值批准记录（append-only）**，建议落地为 `docs/poc/evidence/quality-thresholds.md`，每行至少含：指标名、阈值、样本集与规模、测量方法/脚本、实测值、批准人、批准日期、关联 PoC。
2. **批准权归属**：检索与引用类阈值由产品负责人 + 测试负责人共同批准；涉及安全的阈值（拒绝率、越权漏放 = 0）由安全负责人批准。工程侧只有提议权。
3. **未批准的阈值不生效**：对应 PoC 保持 `PARTIAL`，DG-3/DG-4 生效；不得在文档中把候选值写成「目标已达成」。
4. **改阈值必须留旧结果**：新增一行（不覆盖），写明改动理由与新旧实测值；同一 PoC 的判定按最新已批准阈值重算，并在波次记录中标注重算依据。
5. **测量方法先于数值**：先定样本集、采样规模、置信区间与复现命令，再谈数值；ANN 补跑（ADR-0010）后必须先出实测分布，再提交阈值。

## 替代方案

1. 沿用 `05:74` 的数值直接当阈值：违反「未校准不 PASS」，且把候选值伪装成结论，拒绝。
2. 由工程侧自行校准并写进文档：缺少批准人与产品口径，等同自证，拒绝。
3. 不设阈值，只做定性评审：无法支撑 G-FULL 的量化要求，也无法在回归中防退化，拒绝。

## 后果与验证条件

后果：在阈值批准前，PoC-09 与引用一致性相关结论只能是「测了什么、缺什么」，不能是「达到多少」；ANN 补跑与阈值校准成为 G5 的后置步骤（顺序见 ADR-0010）。验证条件：(1) 阈值记录文件存在且含批准人与日期；(2) 每个引用阈值的文档段落都能指到记录行；(3) 回归中存在至少一条阈值断言（防退化），且失败时给出实测值；(4) 若产品决定降低阈值，必须留旧结果与理由。
